## M1 — PostgreSQL schema, migrations, seed importer

### Migrations
Create `database/migrations/` with ordered, idempotent SQL files:

- `001_init.sql` — enums (`title_type`, `user_role`, `processing_status`, `job_status`, `discount_kind`, `payment_method`, `payment_status`), the full existing catalog schema from `database/database.sql` (actors, categories, genres, titles, movies, series, seasons, episodes, the three M2M joins, watch_progress, favorites) **plus** the new tables in ARCHITECTURE.md §4: users, sessions, oauth_states, video_assets, video_jobs, plans, discounts, discount_redemptions, payments, subscriptions, profiles.
- `002_indexes.sql` — every index named in §4, plus the FK/unique constraints listed under "Changes to existing tables".
- `003_seed_reference.sql` — plans, and the genres/categories that the seed manifests reference.

Rules:
- `create extension if not exists citext;` and `pgcrypto` (for `gen_random_uuid()`) at the top of 001.
- Use `create table if not exists` — **never `drop table`**. The legacy `database.sql` uses `drop ... cascade`; do not carry that over.
- Track applied migrations in a `schema_migrations (version text primary key, applied_at timestamptz)` table.
- `titles` gets `published boolean not null default false`.
- `watch_progress` gets `unique (user_id, id_movie)` and `unique (user_id, id_episode)` (partial unique indexes, since one of the two is always null).
- Money columns are `numeric(10,2)`. Never float.

### Migration runner
A small Go program `microservices/shared/migrate` (or `database/migrate`) that reads the `.sql` files in order, skips already-applied versions, and runs each in a transaction. It must be safe to run concurrently from multiple starting containers — take a `pg_advisory_lock` so only one runner applies at a time and the others wait then no-op.

### Seed importer
`database/seed/` — a Go command that imports `seed/movies/seed.json` and `seed/series/seed.json`:
- upserts genres, actors, categories from the manifests
- inserts titles + movies / series + seasons + episodes
- copies artwork from `seed/movies/data/**` and `seed/series/data/**` into `${MEDIA_ROOT}/thumbnails/` and sets `titles.thumbnail_url` to the served path (`/api/v1/stream/thumbnails/<file>`)
- for **every** movie and **every** episode, registers a `video_assets` row pointing at a copy of `seed/video/video.mp4` as its source and enqueues a `video_jobs` row — seed content goes through the **same** pipeline as an admin upload. Do not build a second playback path for seed data.
- **Idempotent**: running it twice must not duplicate rows. Key on the title name.
- Marks seeded titles `published = true`.

Note: `seed/movies/seed.json` and `seed/series/seed.json` are the real manifests — read them, do not assume the shapes in the READMEs are current. Series entries contain nested `seasons[].episodes[]`.

## M2 — Auth service rewrite (Supabase removed)

Rewrite `microservices/auth` so it owns authentication outright. **Delete** `database/gotrue.go`, `database/login.go`, `database/signup.go`, `database/getSession.go` and the entire GoTrue/JWKS path. Remove `MicahParks/keyfunc` from `go.mod`.

Implement exactly what ARCHITECTURE.md §3 specifies:

- **Passwords**: bcrypt cost 12. Constant-time-ish login (hash a dummy password when the email does not exist so timing does not leak account existence).
- **Access token**: HS256 JWT, 15 min, claims `sub/email/role/iat/exp/jti/iss/aud`, signed with `JWT_SECRET` from env. Verified locally by every instance — no network call, no per-instance state.
- **Refresh token**: 32 random bytes, base64url. Store only `sha256` of it in `sessions.refresh_token_hash`.
- **Rotation**: every `/refresh` issues a new refresh token, revokes the old row, sets `rotated_from`. The revoke+issue must be a single atomic `UPDATE ... WHERE revoked_at IS NULL RETURNING` so two instances racing on the same token cannot both succeed.
- **Reuse detection**: presenting an already-revoked token revokes the entire `session_family` and returns 401.
- **Cookies**: `access_token` (HttpOnly, SameSite=Lax, Path=/) and `refresh_token` (HttpOnly, SameSite=Lax, Path=/api/v1/auth). `Secure` must be driven by a `COOKIE_SECURE` env var — false for local http, true otherwise. Do not hardcode either.
- **Endpoints**: signup, login, refresh, logout, me — exact paths in §6.
- **Middleware**: `requireAuth` (401) and `requireAdmin` (403, role read from the **signed token**, never from a header).
- **Proxy hardening**: in `proxy.go`, **delete any client-supplied `X-User-Id` / `X-User-Email` / `X-User-Role` header before setting your own.** A request carrying `X-User-Role: admin` must not become admin. This is a real vulnerability in the current code — fix it.
- Keep the existing per-container request logging (`[auth3] GET /path -> 200`); it is how horizontal scaling gets demonstrated.
- Keep `cors.go` but drive the allowlist from `CORS_ALLOWED_ORIGINS` (comma-separated env) instead of a hardcoded slice.
- Add the `/api/v1/admin/*` prefix to the proxy route table, targeting `CATALOG_SERVICE_URL`, gated by `requireAdmin`.

### Shared module
Extract into `microservices/shared/` the things catalog/streaming/user/worker will all need, so they are written once: JWT verify, the `X-User-*` context helpers, JSON write/error helpers, pgxpool setup, and a `storage.Store` interface (`Put(key, io.Reader)`, `Open(key) (io.ReadSeekCloser, error)`, `Path(key) string`, `Remove(key)`) with a `LocalStore` implementation rooted at `MEDIA_ROOT`.
